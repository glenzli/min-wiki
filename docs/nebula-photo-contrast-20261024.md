# 创生之柱：照片对照与薄亮边重建 · 2026-10-24

## 学习与观察契约

用户连续指出星云模糊，要求更多对照真实图片。本轮以 Hubble 的创生之柱可见光合成图为主要参照，
观察不同尘柱、柱间负空间、局部受照边缘和稀薄气体。孩子改变观察方向、案例和照明；
转动与照明不改变同一案例的物质数据，独立经典参考也不表示演化顺序。

因果重点仍是气体发射、尘埃遮光及散射共同产生可见形态。亮边不是固体反光，暗处不表示没有物质；
增强色不用于推断温度、元素丰度或裸眼颜色。符号距离场仅描述教学边界的局部坐标距离，
不是天文测距。所有深度、光源位置与光学宽度均由项目设计，不是照片反演的真实三维结构。

## 实现与所有权

`nebulaCloud.ts` 继续拥有经典云轮廓、固定对象坐标、源方向、光学幅度、薄亮边与外侧气体宽度。
Pillars/Horsehead 的 GPU 输入由一份 64³ RGBA 系数场和一份 64³ 单通道符号距离组成。
RGBA 分别提供稀薄气体幅度、亮边幅度、内部尘埃幅度、亮边调色坐标；这些系数不能直接当作最终密度。
Canvas 路径仍从同一连续模型取样为较粗的实际密度/发光场，并近似表现漫射光散射。

`nebulaPortrait.ts` 只负责一般光学接口。它先插值边界距离，再对窄抛物线剖面在当前射线段上的贡献积分，
避免把薄亮边变成宽雾带或因采样相位漏掉整层。内部尘埃、窄亮边、外侧薄气体分别处理。
微弱的中性尘埃可见光来自入射漫射光的示意散射，不是尘埃自发出可见光。
没有表面法线、镜面反光、照片贴面、动态流体或定量辐射输运计算。

只保留当前案例的一份距离数组/纹理：262,144 字节输入；经典 RGBA 仍为 1,048,576 字节，
共同细节场仍为 262,144 字节。离开暗云案例时释放额外纹理，Orion、演化与壳层不保留这份距离数组。
字段替换释放旧上传，普通光照和摄像机操作不重建物质，销毁幂等且销毁后不再分配。
这里记录输入数组大小，不代表测量的 GPU 显存占用。

暗云静止时最多 96 个积分段；Orion 为 80，演化与壳层为 48，导览默认 64。
摄像机手势开始时经典云暂用 64，结束时恢复静止精度，沿用已有控件事件，不新增时钟。
暗云每段增加一次距离纹理读取，初始化另一次；薄亮边和外侧气体共用该读取。
背景球、星点、像素上限及场景寿命沿用原实例，无多案例缓存、新工作线程或后处理目标。

一次 Node CPU 字段准备诊断（与相关测试并行时）为约 1113ms：RGBA 1,048,576 字节、距离 262,144 字节。
这不是浏览器首次加载、GPU 时间或手机帧率测试，不用于作性能提升承诺。
