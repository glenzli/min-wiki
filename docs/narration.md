# 解说稿与配音准备

56 个专题各自维护一份 `topics/<id>/learning.json`。`zh` 和 `en` 是两种语言的独立成稿，不是逐句拼接的翻译片段。网页顶部的「解说稿」入口可以展开正文；「显示画面提示」用于查看分镜。

每份讲稿分成四段，每段包含三个字段：

| 字段 | 用途 |
| --- | --- |
| `label` | 段落标题，方便编辑和定位，不需要朗读 |
| `text` | 给孩子听的口播正文，送入语音合成 |
| `cue` | 画面和操作提示，留给制作人员，不送入语音合成 |

纯口播下载只包含 `text`；分镜下载保留段落标题与画面提示。网页不自动朗读，也没有生成音频文件。

## 一次导出全部稿件

在仓库目录运行：

```sh
node --import tsx scripts/export-narration.mjs /tmp/mini-wiki-narration
```

将生成 112 份纯口播文本、112 份分镜文本，以及按专题和语言排列的 `index.json`。例如：`seed-sprouting.zh.txt` 是中文口播，`seed-sprouting.en.storyboard.txt` 是英文分镜。批量导出与网页下载共用生成函数。修订时先改专题原稿，再重新导出，避免两处内容漂移。

## 配音时的约定

- 使用自然、清楚的讲述语气。按照句意停顿，留出孩子观察与回答的时间，不追求把四段挤进固定时长。
- 四段可分别合成，画面停顿由剪辑控制；不要把括号提示、段落序号或操作说明读出来。
- 讲稿提供完整因果线索；按钮、滑块和镜头仍由专题控制，不依赖音频才能理解知识。
- 合成后人工听一遍多音字、术语和句尾，检查口播与画面对应关系。成稿中的限定词，例如「有些」「通常」「在这个演示中」，不可随意删掉。
- 模型中的颜色、尺度和时间未必是真实值。相关解释保存在同一文件的 `boundary`，学术补充和依据分别在 `academic` 与 `references`。

## 内容验证

`npm test` 检查已发布专题的双语覆盖、学术段落、讲稿分段与参考链接结构，也检查纯口播导出不会混入分镜提示。网页演示及知识准确性仍需要独立审阅；字段检查不能替代科学审校。
