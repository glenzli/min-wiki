# 飞行、浮力、雷电与水循环升级计划

日期：2026-10-22。范围为四个现有专题的内容、动画、空间表达和默认阅读布局；本文件是设计与验收计划，完成证据记录在[整合验收](upgrades-2026-10-22-validation.md)及各专题的 `VALIDATION.md`。本轮只在本地制作、检查和预览。

## 共同方向

参考当前火山、大气专题的因果过程、连续对象、材质层次与观察工具栏，而不照搬画法。默认页面把主要空间留给当前实验：观察内容与讲解方式合为一条工具栏，次要条件收起；播放、进度与当前结果靠近画面，长说明进入解说。手机保留主体的有效比例，避免用空白高度假装放大。

每题先让孩子看见一个可改变的关系，再提供原因、条件、反例和模型边界。儿童与学术模式解释同一个状态。视角切换不重新开始实验，形成进度、环境活动和相机各自有明确作用。

使用真正的三维几何解释形体、空腔、地形接触和空间观察；使用二维剖面解释压力、气流、颗粒接触、孔隙与定量关系。材质先服务于轮廓、接触关系和可读性，再增加细节。不可见的压力、电荷、水蒸气与追踪水份须明确标为编码，不能被误读为照片或实测轨迹。

## 飞机为什么能飞

- 核心问题：很重的飞机为什么在有合适相对气流时能够离开跑道？
- 问题路径：相对气流 → 机翼周围流动与受力 → 跑道支持与离地 → 迎角过大时的失速对照。
- 可变条件：保留速度、机翼姿态与可回退的短时过程；质量、面积、空气密度和系数约定可查。
- 可观察结果：机翼迎角、附着或分离的气流示意、升阻力方向、跑道支持与飞机高度随同一个状态变化。
- 空间制作：默认先展示完整飞机和跑道，机身、机翼、尾翼、起落架都可辨；标记同一片机翼，点击后才进入精细剖面。桌面拉近取景，手机保留完整翼展，避免把大片跑道当成主要内容。整机一起改变姿态，轮胎接地与离地状态一致。
- 动画要求：气流、飞机与力矢量对应同一个采样状态；零气流不能仍有升力；过大迎角不能必然离地；相机不改变实验条件。
- 误解与边界：不使用“上下空气必须同时到达”；不把升力等同向上推力；不把失速说成发动机熄火或升力归零。原系数和流线是教学模型，不新增未经建模的风洞、三维涡流或真实飞机性能结论。

## 浮力

- 核心问题：水怎样托住物体，为什么同一团泥改成空心船后结果不同？
- 问题路径：比较物品 → 水压的向上合力 → 同质量改形 → 载货与船沿 → 浸深和水的密度。
- 可变条件：保留物品、600 g 橡皮泥、0–12 块货物、船沿容积、淡水/海水、悬线浸深；新增观察层不改变这些条件。
- 可观察结果：水线、真实可辨的船内空腔、排水对照、货物与剩余船沿、浮力/重力/张力或箱底支持。
- 空间制作：全面改善水箱比例、玻璃厚度、清澈水面、接触阴影和近看构图；木块、石块、金属与泥船分别具有可辨的形体和材质。既有画面即使科学上成立，也不能视为美术验收通过。量杯为辅助观察，不挤占主要物体；压力与排水采用可切换的近看/剖面观察，不能遮住物体。
- 动画要求：同一团泥与货物保持身份；界面切换不清空载荷；快速修改参数不会让旧过渡覆盖新状态；停稳后不空转。
- 误解与边界：不是“轻的浮、重的沉”；已漂浮物体换盐水后停稳浮力仍等于重量；完全浸没的刚性物体再降低，排水量不增加。压力图要遵守同深等压、随深度增加，不能误画成所有表面力都向上。几何与水位有示意夸张，静水承载不代表抗倾覆或安全载荷。

## 雷电

- 核心问题：云内怎样具备放电条件，一条通道怎样连接并发光，雷声为什么稍后到达？
- 问题路径：冰粒接触与分离 → 云内电荷结构 → 先导与向上连接 → 回击 → 光与声音的传播。
- 可变条件：共享阶段进度、距离与有意义的电荷分离对照；弱条件不强行产生同一次地闪。
- 可观察结果：同一批示意冰粒、上升/下降与电荷区域；固定的分叉路径逐步贯通；接通之后回击前沿和局部照明；声音按模型传播距离到达。
- 空间制作：云内局部使用三维粒子与剖开结构，展示上下运动和接触先后；外部保留已有精细云体、地景和室内观察点插画。声音传播使用清晰的机制图，不为了三维掩盖时间关系。
- 动画要求：先接通再回击；分叉形状稳定且可回拖；强光受同一回击进度约束，无独立频闪或自动声音；观察点不变成露天追雷场景。
- 误解与边界：展示的是简化负地闪，不能概括所有闪电；符号是电荷区域/状态编码，不是可见电子轨迹；冰相起电依赖条件，不能讲成所有碰撞固定转移相同电荷。声波示意不是可见光圈、危险半径或线性地图。

## 水循环

- 核心问题：同一批水在流域里会去哪里，为什么并非每一份都立即回到海里？
- 问题路径：流域总览 → 成云与降水 → 地表/土壤分流 → 河道与地下储存 → 冰雪及较长时间尺度。
- 可变条件：保留湿度、暖雨/冰相路线、地表类型、可逆批次进度；地下水与冰川实验保留独立收支和时钟。
- 可观察结果：100 个稳定示意水份沿分支进入不同储存位置；干湿、透水与铺装条件呈现不同去向；冰与融水不跳成无关对象。
- 空间制作：建立可近看的三维流域，山脊、坡地、河道、湖海与冰雪拥有一致位置；水面与地形真正接触。云微物理、孔隙与收支继续使用清楚的局部视图。
- 动画要求：全景与局部围绕同一地理锚点；河道水和追踪标记共用路径；镜头不改变100份批次的身份和历史；隐藏或离开窗口暂停独立实验。
- 误解与边界：水蒸气不可见，云是液滴/冰晶；教学批次不是全球占比。不能把所有储存强行画成一个闭合圆，也不能把独立地下水/冰川收支加到主批次中。三维地形不等于测量地图或流体求解。

## 分工与验收

四个主题分别在自己的目录开发；公共登记表、Reader 和火山/大气已有改动不属于本轮各主题的编辑权限。开发使用 GPT-6.1 Sol、max；最多三个开发子任务同时运行，第四题在位置释放后接入。整合者负责共同计划、最终构建、实际浏览器检查与交付说明。

1. 模型与几何：按题检查力平衡、接触、阶段先后、分支与稳定身份；新测试针对真实契约，不用截图数量或模型通过替代目视检查。
2. 内容：中英文条件等价，新增科学解释有对应一手来源；学习内容遵守现有三节学术笔记/四段解说结构，静态正文与口播投影一致。
3. 生命周期：暂停、回拖再前进、快速切换、隐藏恢复、减少动态效果；三维失败时保留解释和可操作回退，资源有上界且释放完整。
4. 集成：源码定稿后执行一次仓库完整门禁；针对修复重跑受影响检查，构建产物与最终源码一致。
5. 浏览器：每题中文/英文、桌面/390 px；检查起点、中间态、结尾与有意义的对照，观察真正的主体大小、材质/空间关系、按钮可用性与相关运行错误。保存可查看预览及截图证据。
6. 报告：分别说明已实现、测试、目视检查及未覆盖情况；本轮不自动提交、推送或部署。
