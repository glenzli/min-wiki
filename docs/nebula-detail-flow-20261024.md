# 星云气尘细节与直接操作 · 2026-10-24

## 本轮问题与学习路径

用户指出上一版仍模糊，创生之柱像实体石柱，星云选择需要打开过多层级。
本轮让孩子先直接选择一个对象，观察亮气体、暗尘和空隙，再改变照明、转动同一份物质。
命名参考仍是不同对象，按钮顺序不表示演化。此记录不把实施者的检查等同于用户视觉接受。

## 画面调整

- 经典云场由 48³ 提高到 64³，经典参考的积分由 48 步提高到 80 步。
  细节场由 32³ 改为 64³，各向同性的相关结构混合细小密度变化，不绘制重复薄亮纹。
- 创生之柱和马头分别保留不等高长柱、头颈与母云。致密内部、稀薄云絮和后方亮气体分开，
  尘埃密度有疏密，边缘有不规则过渡。去掉有限差分表面法线造成的实体亮边，不添加镜面反光。
- 亮背景主要位于吸收云后面，前方不再覆盖一层均匀发亮的柱体表面。母云边缘和透明度变化，
  马头颈部连续连接母云；转动仍能看到固定于对象坐标的示意深度。
- 参考仍为 [猎户座](https://esahubble.org/images/heic0601a/)、
  [创生之柱](https://esahubble.org/images/heic1501a/) 和
  [马头](https://esahubble.org/images/heic0105a/) 的官方合成影像。
  马头影像包含可见光及近红外输入。没有从照片反演三维密度，也没有将照片贴到模型上。
  颜色增强、光源位置、深度和亮度都是教学设计，不是裸眼颜色或定量辐射输运结果。

## 操作调整

- 六个章节直接显示，短标签配完整的可访问名称，不再藏在章节菜单中。
- 猎户座、创生之柱、马头、行星状星云、超新星遗迹合为一个五按钮选择组。
  不再先开案例折叠、再选机制、再找经典参考。
- 下一行直接改变发射、散射、遮光条件，或打开壳层；恢复角度也直接可用。
  详细解说和阅读深度保留在 Reader 自己的入口。
- 桌面章节一行六项、案例一行五项；390px 手机章节 3×2、案例 3+2，触控高度 44px。
  切换保留其他章节的演化进度、质量路径、光照、所选经典云和 URL 参数。

## 所有权与资源边界

`nebulaCloud.ts` 拥有形态、密度、发光、尘埃、调色坐标及示意源位置。
`spaceVolume.ts` 只保留当前一份物质场：经典云 64³ RGBA（1,048,576 字节），
演化和壳层仍为 48³（442,368 字节）；48³ CPU 累积数组为 1,769,472 字节。
这些是输入数组大小，不是测量得到的 GPU 占用。

共同 `nebulaPortrait.ts` 保留一份 64³ 单通道细节纹理（262,144 字节），每步三次细节采样。
恒星专题编译上界 80 步，经典云使用 80，演化/壳层 48；宇宙导览默认仍为 64。
字段尺寸或数据引用改变时验证新纹理并释放旧纹理，同尺寸普通光学更新复用现有纹理。
无多案例缓存；销毁幂等，销毁后不再分配。没有新增时钟、工作线程、远程纹理或后处理目标。
照明、摄像机和不影响当前独立案例的演化参数不重建物质。

Canvas 降级仍只惰性保留当前参考的 48³ 场，最多 144² 像素、40 次深度采样，明确是平面示意。
像素比上限 1.75、绘图缓冲上限二百万像素、无独立 WebGL 动画循环的边界保持。
没有测量物理手机帧率，也不宣称上述采样提升没有性能成本。
