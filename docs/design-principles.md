# 小小百科：专题设计原则与验收要求

整理日期：2026-09-20。适用于新增专题、旧专题优化、多个专题融合，以及相应的内容、封面和工程实现。

本文件总结黑洞、太阳系、风、火山及叶片、雷电等近期迭代中的共同要求。它是后续工作的设计基线，不是“全站已经满足全部要求”的验收报告。部分参考实现仍在其他任务中迭代；使用前核对当前源码和验证证据。

## 1. 产品定位：可探索的解释，不是动画陈列

孩子先通过操作和观察发现关系，家长和深入读者再了解机制、条件与证据。好看的画面是入口，能够回答“为什么、条件变了会怎样、哪里不能这样理解”才是专题完成的标准。

**降低理解门槛，不降低知识深度。** 面向孩子不等于故意删去机制、细节和例外。用可观察对象、具体操作和逐层问题建立入口，让愿意继续追问的孩子也能深入；不要把所有有意思的细节都藏进“家长版”。短句、少术语是表达选择，不是限定知识量。

收敛目录时先区分三种情况：共同机制或完整对象能够形成递进问题链的，融合并补足观察；虽短但有独立可探索机制的，保留或围绕对象展开；暂时只有几句结论、缺少可观察变化且价值不高的，先列为后续候选，不为凑专题数量强行扩写。不能仅凭标题相似、篇幅短或页面少就删除。`learning.json` 的 3 条学术摘要、4 段解说是现有组件契约，不是整篇正文和互动深度的上限。

要求等级：**必须**是新增或受本次修改影响的范围内的验收条件；**建议**是默认选择，有明确理由可采用其他方案。不要求一次性重写未触及的旧专题。例外应说明原因、影响和替代验证。

每次开工前，先写清六件事：

1. 核心问题：读者最终应理解什么，而不只是看见什么？
2. 可变条件：读者能改变什么，哪些条件保持不变？
3. 可观察结果：哪个形状、运动、分布或读数会随之改变？
4. 因果链：从什么前提，经由什么机制，产生什么结果？
5. 容易误解之处：画面最可能造成哪一种错误理解？
6. 边界与依据：哪些是观测、推断、模型计算或教学示意，分别有什么来源？

## 2. 专题融合：组织理解路径，不只合并菜单

必须先确定主题内的关系，再决定页面和章节：

- 相同对象的不同观察层次，例如太阳系全景、某颗行星、固定地区、内部结构。
- 同一机制的不同条件或分支，例如黑洞飞掠、潮汐瓦解、伴星持续供给。
- 有证据支持的前后过程，例如岩浆补给、通道推进、喷出、堆积与后续变化。

每一站应回答“上一站学到的什么仍然成立？这里增加了什么条件？接下来观察什么？”。共享的颜色、粒子、方向、参照物和操作词汇应帮助迁移理解。

以下不算融合完成：只增加父目录、页签或 iframe；章节间反复重置相同条件；讲解重复却没有递进；把所有案例强行排成一条必然演化路线。

不能因为主题相近就暗示物理等价：海岸环流不会自然升级成台风，龙卷风不是缩小的台风；火山湖不是所有火山的终点；恒星遭遇与伴星供气不是同一过程的两个进度值。合并也不要求把不同引擎改成一个巨型模型。不能形成连贯问题链的主题，可以保留独立专题和关联链接。

验收：读者只看章节标题、观察提示和关键画面，应能说出两章之间的联系及差别。

## 3. 科学机制：显示原因，允许不同结果

- 必须呈现本题关键前置过程。闪电不能只有一条亮线；解释喷发不能只有喷出的粒子。
- 因果相关的画面必须消费同一模型状态。通道尚未贯通时，地表不能提前出现由该通道产生的喷出物；改变山体后，熔岩与碎屑的碰撞边界也必须一致。
- 当科学问题涉及“是否发生”，必须有不发生、减弱、中断或另一种去向的对照，不能让每组参数最后都播放相同结果。
- 不用更大的粒子数、泛光或震动代替机制。不用文字声明“是示意”来容忍与核心解释相矛盾的画面。
- 模型应保持必要的不变量，例如物质身份、区室边界、轨道关系或单调推进。只声明并测试真正建模的守恒关系，不能把一个教学插值称作完整物理求解。

颜色、箭头和粒子是编码：必须一致并在必要处给出图例。它们不自动代表真实色彩、单个分子、实际流速或温度。改变编码要同步所有视角、讲解和图例。

验收：改变一个条件后，能够指出“模型状态哪里变了，画面为什么变了”，并展示至少一个有意义的对照。

## 4. 连续性：同一对象、同一地点、同一段历史

### 对象与空间连续

- 在观察同一过程时，优先保留同一批粒子、网格、地貌或生长位置。不要用“球体消失、另一个环出现”冒充物质的连续演化。
- 宏观到微观、轨道到近地、整球到剖面的过渡必须有可追踪的锚点。可以交叉淡化或采用解释性切换，但不能静默更换对象或地区。
- 选择地点时，经纬度、球面标记、相机目标、局部地形和讲解必须一致；极地不能落到普通荒漠，岩石地面不能无故变成海岸。
- 气态世界的接近不是降落到凭空增加的固体地板。观察镜头不是自由落体模拟，除非真正计算了相应动力学。
- 纹理应绑定对象或空间坐标，随机细节应稳定生成；不能在每一帧重新随机导致闪烁、游移或旋转时纹理跳动。

### 时间与状态连续

- 区分形成进度、持续运动和观察镜头三个概念。形成达到终点后，气流、云层、恒星表面或持续喷发不应无故完全冻结；但也不能擅自循环重演形成过程。
- 暂停、回放、拖动的作用必须明确。若有独立时钟，应标清“暂停活动”和“暂停下降”等范围。
- 拖动进度必须可重复、可回退；同一参数与进度应得到一致状态，或明确说明模型只支持向前运行。动画插值不能覆盖较新的用户选择。
- 换讲解模式、参考线或视角不得重置实验。章节/对象切换应保存合理状态，并明确哪些操作重置当前案例。保留内存状态不等于刷新、语言切换后仍能恢复。
- 沉积物、侵蚀痕迹、物质尾迹等历史结果应随过程保留或按机制变化，不能因切镜头清空。

验收：至少检查一个中间态；执行前进→回退→再前进、快速换章→返回、换视角→继续播放，观察身份、位置与历史是否保持一致。

## 5. 尺度：展示“大”与“小”，但不能制造假比例

- 明确比较的是质量、半径、直径、距离、时间还是天空中的角尺寸，不能混用。
- 定量比较必须有单位、数据来源和参照物。同一帧中声称等比例的对象，应使用同一长度换算与合适投影；不要以透视近大远小冒充物理尺寸差异。
- 跨量级可使用连续缩放或对数控制轴，但必须说明映射方式。对数变化的镜头不意味着帧内几何也用对数半径。
- 若物体大小、距离、层厚或时间分别夸大，必须明确标识，不能让屏幕尺寸被误读为测量结果。
- 小于像素的天体不能悄悄增大圆盘以保持可见；可用定位标记，并说明标记不是直径。
- 重叠或同心的比较图必须说明不是实际空间关系；云系跨度、强风范围与风眼不能当成同一个尺寸；黑洞视界、阴影与吸积盘也必须分别说明。
- 采用取整值、无自旋等效量、代表场景或未标定时间时，应写在相关画面附近，不只藏在长篇资料末尾。

验收：读者能回答“这一段标尺代表什么？哪些尺寸可以直接比较？哪些不能？”。

## 6. 视觉：材质、几何与运动共同解释对象

### 选择表达手段

三维不是统一指标。需要旋转、遮挡、空间层次、体积或连续接近时优先考虑三维；需要精确比较、因果图或剖面说明时，SVG/Canvas/二维图可能更清楚。混合使用可以，但必须处理好坐标与状态衔接。

写实程度应足以避免误导，并突出当前观察重点：

- 曲面、容器和地貌要有一致透视、接触关系、厚度与遮挡；不是堆叠椭圆和色块就等于立体。
- 气体、火山灰、熔岩、水、冰、叶肉、云层应具有可辨认的边缘、透明度、层次或流动特征。
- 着色应与分布或结构有关。例如色素增多不应表现成无缘由的中心红色圆形擦除动画。
- 涡旋和球面材质必须检查极点与接缝，避免出现从极点放射的伪条纹；剖面内运动必须限制在对应层，不能穿越边界。
- 动态细节要有解释依据。未知内部结构不能为了“活起来”而编造确定的环流。

建议使用窄视角或正交投影做形状/尺寸比较；自由观察可以有透视，但镜头不得把恒星、行星等主体拉成不自然的广角形状。泛光、镜头震动和粒子密度要克制，主要轮廓和关键关系必须清晰。

### 封面与正文分工

封面是有统一审美的编辑插画，不是科学测量图。建议保持 3:2 构图、清楚主体、细腻材质、自然光线与克制色彩；专题可根据对象采用不同明暗，不要求宇宙与植物同一配色。

必须在目录真实卡片尺寸和单条搜索结果中检查裁切、辨识度、清晰度与风格一致性。不能用临时几何占位图冒充最终封面，也不靠图内小字承担重要解释。

生成或外部素材必须保存来源、许可/署名或生成提示词，明确插画不是观测照片。生成插画适合封面和非定量素材；精确几何、标尺、曲线和数据标签应由可核验代码绘制。发布使用响应式压缩资源，遵守[图片交付约定](performance.md)，不让目录下载大幅原图。

## 7. 界面与无障碍：把画面还给观察

- 主要解释、读数和控制放在画布外。必要标注靠近对象但避免遮挡，可关闭；关闭标注后仍应保留必要的尺度或在画面外提供等价解释。
- 控件只呈现当前场景支持的功能，不留无作用的视角、按钮或参数。明确当前选择、加载、失败和禁用状态。
- 儿童版侧重观察和提问，学术版解释同一画面的原理、变量、假设与限制，而不是另一个实验。
- 儿童版让主画面和操作占主导，用一至三句讲清当前现象及关键因果，隐藏多余的技术读数和重复说明。学术版可以在同一场景的侧栏增加机制、变量、公式、证据与限制；侧栏应可阅读、可滚动，不能靠缩小字号硬塞。内容确实超出侧栏承载能力时，再把延伸研究放到画面下方。公式须交代变量、条件和适用范围；没有可靠模型时不为显得“学术”而硬塞公式。
- 使用原生语义按钮、选择框和滑块、可见焦点及合适的 ARIA 名称/状态。不能只靠颜色说明条件差异，也不能只靠声音传递结论。
- 关键操作支持键盘和触摸，控件沿用共享的基础尺寸与主题变量。390 px 中英文都必须可用；无横向溢出只是底线，还要检查画布、按钮换行和长英文标签。
- 声音不得自动开启。显著推进教学状态的播放应由用户发起；若环境活动默认运行，必须有明显暂停、尊重减少动态效果偏好，并明确其与过程进度的区别。
- 支持 `prefers-reduced-motion`，减少非必要镜头/过渡运动；不应因此隐藏解释、破坏最终状态或锁死操作。
- 渲染失败时，说明和导航仍应可用，并给出恢复或重试途径。

## 8. 内容与双语：两种深度，不是两套事实

必须保持中文与英文在机制、限定条件、风险提示和不确定性上的一致，不把“可能、通常、在本模型中”翻译成确定结论。儿童用语可以简化术语，不能改写因果关系。

每题应提供观察问题、操作提示、解释、常见误解、模型边界和对应来源。优先采用直接支撑主张的机构资料、原始研究或数据；不能仅放几个权威机构首页。特定数据应记录单位、取值方式及适用条件；不得用代码测试通过代替科学依据。

当前仓库契约，而非永久教育学定律：`learning.json` 的中英文各有三节学术笔记、四段解说，并共享参考资料。若需要改变数量，应同时修改 schema/消费方/测试，而不是只塞入新段落。具体字段与导出约定见[解说稿说明](narration.md)和 [learning 测试](../tests/learning.test.mjs)。

口播正文与画面提示分开；下载的纯口播不含按钮指令和制作注释。网页讲解不应依赖已生成音频才能成立。实际术语、画布标注、无障碍说明与目录元数据都在双语检查范围内。

## 9. 工程边界：体验统一，模型仍有清楚归属

- 专题拥有模型、场景、参数、时间、内容与测试；共享平台拥有导航、语言、主题、知识区呈现。不要把专题科学规则塞进目录或通用播放器。
- 新的完整职责可以有独立模块；不要仅为缩短文件拆出始终一起变化的零散片段。模型、渲染和 UI 应消费同一组真实数据，避免图、文字和测试各写一份常量。
- 统一主题的控制器负责路由、选择、状态恢复及场景生命周期；子模块负责自己的物理/教学规则。复用模型不等于把旧页面的 UI 原封不动嵌入。
- 不强制所有主题采用同一缓存策略。按需加载并在切章时销毁，或保留有限个已访问场景都可以；必须有资源上界、暂停规则和清理逻辑，不能无限累积 canvas、Worker、事件监听和 GPU 资源。
- 异步准备必须防止旧结果写回新场景；渲染器销毁后不能再挂载晚到的结果。取消、异常、重试与快速切换必须覆盖。
- 页面隐藏或离开时停止不必要更新与音频；往返缓存恢复不能产生重复实例或跳跃的累计时间。
- 首页不加载专题引擎。稳定纹理/几何不应逐帧重建，DOM 文案不必跟着每个渲染帧重写；重计算、缓存和 Worker 的引入应针对测得的问题。

性能说明必须分清首次加载、首次计算、缓存后切换、稳定播放与长时间切换后的资源占用。文件更小或出现共享大包警告，都不能单独证明运行更快或更慢。未经测量不要声称固定帧率、启动时间或 Web Vitals 改善。

## 10. 目录与迁移：减少重复入口，不破坏旧链接

融合后目录应体现主题，而不是重复列出所有已吸纳子项目。旧 URL 应进入明确对应的场景，保留有效的语言、子路径部署前缀和适用参数/锚点；旧页面实现可移除，仍被新主题消费的模型和资产不可误删。

当前 `parentTopic` 只支持同分类、已发布父项的一层关系；搜索包含已发布子项的词汇，结果返回父项。不要用 `draft` 隐藏已经发布的旧入口，否则它可能退出生产构建。详情见[架构约定](architecture.md)和[目录模型](../src/catalog/model.ts)。

暂时不值得作为独立目录卡片、又没有可承接其完整内容的父主题时，可将已发布顶层专题标为 `listed: false`。这会从目录、分类计数和搜索中收起该卡片，直接 URL 和正式构建仍保留；这不是科学内容已融合或页面已修好的证明。恢复展示前，应重新通过本专题的知识链、关键画面和双语浏览器验收。

路由必须验证参数并有合理默认值。浏览器返回/前进、直接访问和刷新应到达可解释状态。用户说“删掉旧项目”时，要区分移除重复目录、旧 UI、兼容入口和底层资产的具体范围。

## 11. 验收：数值正确、画面正确、行为正确分开证明

交付前按改动风险选择验证，记录命令、源码/产物身份、实际操作及未覆盖项；不要复制历史测试数量充当本轮证据。

| 改动 | 至少需要的证据 |
| --- | --- |
| 纯开发文档 | 对照源码/契约，检查链接、格式与状态表述；不为文档反复重建全站 |
| 单个模型或交互修复 | 所属模块测试；关键数值、不变量、边界和受影响浏览器操作 |
| 用户文案、双语、封面 | 翻译/图片一致性检查；两种语言或目录实际尺寸下的目视检查 |
| 场景/章节融合、路由或共享接口 | 受影响契约测试、生产构建、打包后真实入口与旧路由验证 |
| 新专题、广泛集成或发布 | 仓库完整门禁 `npm run check`，以及实际生产产物的浏览器验证 |

已有验证仅在相关源码、配置、资源与环境未变时复用。修复一个已定位失败后可先重跑其受影响检查；不能声称未重跑的完整套件“本轮全绿”。生产预览只读取构建产物，源码修改不会自动更新它。
