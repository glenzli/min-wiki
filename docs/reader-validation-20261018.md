# 互动条目与阅读器验证 · 2026-10-18

> 以下是选型阶段的历史验证记录。其隔离样例已随全量迁移移除；当前入口、完整范围与验证见 [Reader 全量切换](reader-migration.md)。下文预览地址和源码路径描述当时状态。

## 结论

“影子”二维实验和“地球和月亮”三维实验都能通过 Markdown Book 0.7.0 的公开组件接口运行。动画、双视角和贴图并未要求另一套科学引擎。可以复用的稳定边界是组件挂载、取消、清理、有限 JSON 实验状态，以及 Markdown、公式和静态输出等能力。

完整阅读器仍围绕书籍、章节和正文组织。若保持 Mini Wiki 以演示为主、条目双语与独立资源交付的定位，建议后续采用轻量的 `wiki-reader`：条目库留在 Mini Wiki，阅读器负责展现与构建，glenzli 负责网站承载。先沿用小的组件契约，不建立第三个大型通用框架，也不为验证而给 Markdown Book 增加多种产品模式。

这是后续拆分的建议；本轮交付是隔离样例和证据。未迁移其他条目，未修改正式目录、站点或 Markdown Book，未创建独立 GitHub 仓库，未提交、推送或部署。用户已授权必要时通过 GitHub 创建独立阅读器项目，这项授权不等同于已经创建或发布。

## 验证怎么做

当时源码入口为 `experiments/reader-validation/`（现已移除）。准备脚本读取当前科学模型、渲染器、素材与翻译，在临时目录投影出符合真实书籍边界的两份清单。没有把旧网页放进 iframe，也没有重写光线投影或月相模型。

二维适配器复用原 SVG 与 `drawShadowScene`，重新连接组件内控件、有限播放和状态。三维适配器复用 `TopicScene`、`MoonObserver`、月相/比例模型与逐阶段解释；生成副本只做如下边界转换：

1. 将引擎与 OrbitControls 导入指向 Markdown Book 的公开 Three.js 入口。
2. 为场景增加组件根节点，将三处 `document.getElementById` 查询局部化。
3. 保护初次隐藏挂载时的零尺寸，避免相机得到无效宽高比。
4. 因打包器不接受 WebP 导入，验证副本将三张纹理转为数据 URL 模块。
5. 翻译桥接保留专题字典和公共字典的回退顺序，不把缺失词条静默当作英文。

原始文件不被这些转换覆盖。生成的 `source-receipt.json` 记录源提交 `c2882f86394df834a56df6a022d2fd271f978b4a`、输入 SHA-256、工具版本和转换次数。源工作树含既有未提交修改，因此提交号本身不代表全部输入。

## 实际复用边界

| 能力 | 观察结果 | 对后续拆分的含义 |
| --- | --- | --- |
| SVG、Three.js 与有限动画 | 两个样例均能操作；太空视图可拖动；地球视角共用原月面 | 保留题内模型/场景；阅读器无需拥有科学规则或统一实验时钟 |
| 组件生命周期和 session | 参数、视角、参考影子可恢复；恢复保持暂停 | 可以沿用 `mount({element, props, signal, session})` 这一级小接口 |
| 说明、公式、来源和静态回退 | 普通 Markdown、公式、来源链接和“查看静态图”可用 | 文本解析与呈现是明确的可复用能力，但不必因此采用书籍的产品外壳 |
| 纹理资源 | 未桥接时实际构建失败，报告三处 `No loader is configured for .webp` | 需要条目资源构建/定位契约，不能直接采用本次内联桥接作为正式发布方案 |
| 双语内容 | 组件和正文可分别生成中文、英文；Reader 设置只改变界面 | 条目需要一个身份下的语言选择与路由，不能把切界面语言当作内容翻译 |
| 演示布局 | 中英桌面和手机均可使用；书籍导航、段落与演示共用正文流 | 演示优先的画面/操作/解释布局需要单独设计；本轮没有修改 Reader 的排版来掩盖差异 |
| 版本与独立性 | 原仓库 Three.js 0.170.0，Reader 固定 0.186.1 | 只证明此场景兼容；不得据此升级整个条目库或承诺所有 addons 均兼容 |
