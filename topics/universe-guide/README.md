# 宇宙探索地图 / Universe guide

An interactive taxonomy and question map, not another physical simulation. `content.json` owns bilingual examples, contrasts and four paths. `model.ts` owns stable identity and family selection; `main.ts` projects these into accessible controls. The guide now owns nonmetric spatial portraits for identification and energy-source comparison. Three-dimensional physical studies, process clocks and measured scaling stay in their topic owners.

- Core question: what kind of thing does a familiar astronomical name describe?
- Variable: selected family and example, retained viewing angle, and energy view for Sun/red dwarf/white dwarf; each example retains its named contrast and scientific clues.
- Observation: spatial form, noun-level identity, illumination, membership and follow-up experiment change together. Opening a simplified stellar sector reveals a qualitative energy source; fixed arrows denote outward energy transfer, not moving matter or measured layer thicknesses.
- Causal limit: no physical outcome is calculated. Learning paths are not evolutionary sequences.
- Misconceptions: meteor versus comet, nebula versus galaxy, supernova event versus remnant, dwarf planet versus size alone, system versus member.
- Evidence: NASA topic pages are linked from each example, with the substantive source list in learning.json.

`?object=<id>` restores the selected example, tolerates unknown values and retains language. `detail=energy` restores the supported stellar energy view; unsupported objects keep their ordinary portrait. Hand-rotated poses persist for the 23 known objects while the viewport remains mounted; refreshing or remounting resets the angles. All navigation uses the established deployment-base/language helper. Known named-body pairs use compressed size differences while preserving their size order, independent of which object is selected. Clouds, systems, events and unspecified black-hole masses instead use visibly divided close-up windows; no universal class diameter is invented. The catalog reuses the cosmic-scale editorial cover with its existing provenance.

`portraitModel.ts` owns the explicit known-body size relations, compressed fitting and bounded deterministic populations; `portraitScene.ts` composes two live portraits and owns camera/gesture state and GPU lifetime. `src/visuals/stellarPortrait.ts` owns emissive photospheres, stable granulation/spot fields, display glare and optional energy sections. `src/visuals/nebulaPortrait.ts` owns retained 3D gas/dust fields and their front-to-back emission/extinction integral. Both are shared rendering owners consumed by the guide and stars topic; scientific state and evolution remain topic-owned. `portraitViewport.ts` owns lazy loading, latest-input projection, fallback, retry and disposal. Guide identity, size-order policy and camera/lifecycle composition remain local to the guide. The existing CSS symbols are used only while loading or after rendering failure. Reading, object selection and study links remain available in that state.

Performance: one renderer, two live object roots, up to 4,200 point samples per portrait plus 180 decorative background points; stellar sphere grids are 80×56, other spheres 64×40. Fusion stars retain one 256×256 RGBA generated map each, with mipmaps; compact remnants have no surface map. Stellar glare is bounded to radius 1.15 around a radius .85 photosphere. Each nebula retains one 64³ RGBA volume and one 32³ single-channel detail volume (1,081,344 bytes combined before upload); at most 64 samples integrate each ray, terminating early when transmission is negligible. Only the current pair retains these arrays and GPU copies; fields are not rebaked on rotation. Object-owned maps are released with their portrait, alongside at most two selected planet maps and one 128×128 glow texture. Planet maps load only when relevant; stale loads are disposed. DPR is bounded by 1.75 and the drawing buffer by 1.8 million pixels. There is no animation loop or simulation time: gestures, selection and resize coalesce into event-driven frames. Hidden documents cancel pending drawing; pagehide disposes the scene, and a persisted pageshow creates one fresh renderer from the current selection. Rendering failure retains the latest selection for retry. OS reduced-motion needs no alternate timeline because there are no animated transitions or automatic rotations.

Earth, Jupiter, Neptune and Moon reuse the existing Solar System Scope/INOVE educational maps under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/), with attribution shown in the explanation and provenance retained in [the original asset attribution](../solar-system/assets/ATTRIBUTION.md). No remote assets are fetched. Other geometry, soft cloud fields and photospheres are original code illustrations; white-dwarf surface detail is deliberately restrained rather than inventing landforms. Energy-source distinctions were checked against [NASA star types](https://science.nasa.gov/universe/stars/types/) on 2026-10-23.

Appearance is representative and exposure-compressed. Enlarged granules and spots illustrate a photosphere rather than a measured map; the white dwarf is a hot blue-white case, not every white dwarf's colour. Glare expresses display exposure and is not a measured corona. Nebula gas, absorbing dust lanes, embedded sources and shell morphology are constructed in the same object coordinates; changing direction changes optical path and occlusion without rebuilding the density field. These are teaching constructions, not observed 3D reconstructions or measurements of temperature, density or spectra. Additional primary sources: [NASA photosphere](https://solarscience.msfc.nasa.gov/surface.shtml), [NASA red-dwarf starspots](https://science.nasa.gov/universe/exoplanets/proxima-centauri-might-be-more-sunlike-than-we-thought/), [NASA Hubble nebulae](https://science.nasa.gov/mission/hubble/science/universe-uncovered/hubble-nebulae/), and [NASA/ESA Veil filaments](https://science.nasa.gov/missions/hubble/hubble-revisits-the-veil-nebula/).

The guide's compact select indicators are local presentation. Wiki Reader's `reader/style.css` normalizes native select padding with `!important`; native `appearance:auto` leaves arrow placement to the browser. The guide keeps native select semantics, reserves 40px of end padding through a narrowly scoped override, and places a pointer-transparent chevron 16px inside its own label, using the Reader's theme-aware muted colour. At 639px and below, one full-width native chooser groups all 23 objects under five category labels, preserving complete English names without squeezing the stage. Returning to desktop restores the two selectors with the selected object/family unchanged. No Markdown Book runtime participates in this page, and no Reader dependency or global control styles were modified.
